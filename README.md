# 방문객 출입등록 웹 애플리케이션 (테스트 프로토타입)

종이로 작성하던 방문객 출입관리대장을 대체하기 위한 Streamlit 기반 웹 페이지입니다.
방문객이 정보를 입력하고 사내 담당자를 검색해 선택하면, 방문 기록이 CSV 파일에 저장되고
담당자에게 "방문 도착 안내" 메일을 보내는 과정을 **테스트 모드**로 시뮬레이션합니다.

> ⚠️ 현재 단계에서는 실제 이메일을 발송하지 않습니다. 화면과 서버(터미널) 로그에서
> "누구에게, 어떤 제목/본문으로, 언제 보낼 예정이었는지"만 확인할 수 있습니다.

---

## 1. 파일 구성

| 파일 | 역할 |
|---|---|
| `app.py` | 방문객 등록 페이지 전체 로직 (화면, 검증, 서명, 저장, 테스트 메일) |
| `pages/1_관리자_페이지.py` | 관리자 전용 페이지: 방문 기록 조회/검색/퇴실일시 수정/엑셀 다운로드/이메일 발송 테스트 |
| `utils.py` | `app.py` 와 관리자 페이지가 함께 쓰는 공통 로직 (경로 상수, 환경변수 로딩, 방문 기록 로딩/수정, 엑셀 생성, 이메일 테스트) |
| `employees_dummy.csv` | 테스트용 직원(담당자) 명단. 실제 이메일이 아닌 example.com 주소 사용 |
| `visitor_log.csv` | 방문 등록 시마다 한 줄씩 쌓이는 방문 기록 파일 (자동 생성/추가) |
| `report_recipients_dummy.csv` | 이메일 보고 테스트용 수신자 더미 명단 (4명, example.com 주소) |
| `signatures/` | 방문객이 등록 화면에서 직접 그린 서명 이미지(PNG)가 저장되는 폴더 (자동 생성, GitHub 제외) |
| `requirements.txt` | 실행에 필요한 파이썬 패키지 목록 |
| `.env.example` | 이메일 테스트 모드/관리자 비밀번호 등 환경변수 예시 (그대로는 사용되지 않음) |
| `.gitignore` | 개인정보가 담긴 파일(`.env`, `visitor_log.csv`, `signatures/` 등)을 GitHub에 올리지 않기 위한 설정 |
| `README.md` | 지금 보고 있는 설명 문서 |

Streamlit은 `app.py`(메인 페이지)를 실행하면 같은 폴더의 `pages/` 아래 있는 파일들을
자동으로 인식해 화면 왼쪽 사이드바에 추가 페이지로 보여줍니다. 그래서 관리자 페이지를
따로 실행할 필요 없이, `streamlit run app.py` 한 번이면 방문객 등록 페이지와 관리자
페이지 모두 사용할 수 있습니다.

## 2. 직원(담당자) 명단 형식 — `employees_dummy.csv`

다음 5개 열이 **반드시** 있어야 합니다. 열이 없거나 파일 자체가 없으면 앱 실행 시
화면에 알기 쉬운 오류 메시지가 표시됩니다.

```
employee_id,name,department,email,active
E001,김민준,경영지원부,kim.minjun@example.com,Y
```

- `employee_id` : 직원을 구분하는 내부 식별값. 동명이인이 있어도 이 값으로 정확히 구분합니다.
- `active` : 값이 정확히 `Y` 인 직원만 방문객 검색 결과에 노출됩니다. (`N` 이거나 다른 값이면 검색에서 제외)
- `email` : 방문객 화면에는 절대 노출되지 않고, 서버 내부에서만 담당자 조회에 사용됩니다.

---

## 3. 담당자 검색(자동완성) 동작 방식

- 화면의 검색창에 이름 일부 또는 부서명을 입력하면, 그 즉시(별도 검색 버튼 없이) 아래에
  일치하는 후보 목록이 `이름 | 부서` 형식으로 표시됩니다. (일반 드롭다운이 아닌 검색형 목록입니다)
- 후보 목록에서 **반드시 한 명을 선택**해야 등록이 가능합니다. 텍스트만 입력하고 아무도
  선택하지 않으면 "등록하기"를 눌러도 오류 메시지가 표시되며 저장되지 않습니다.
- 내부적으로는 이름이 아닌 `employee_id` 를 선택값으로 사용하므로, 이름과 부서가 같은
  동명이인이 있더라도 서로 다른 사람으로 정확히 구분됩니다.

---

## 4. 등록 시 처리 순서

"등록하기" 버튼을 누르면 다음 순서로 처리됩니다.

1. 필수 입력값(성명/회사명/연락처/목적/장소)과 개인정보 동의 여부, 담당자 선택 여부를 검증
2. 선택된 `employee_id` 로 담당자 이메일을 내부에서 조회 (화면에는 표시하지 않음)
3. `visitor_log.csv` 에 방문 기록 한 줄을 추가 저장 (UTF-8-SIG 인코딩 → 한글이 엑셀에서도 안 깨짐)
4. 등록 일시를 한국 표준시(KST, UTC+9) 기준으로 자동 기록
5. 이메일 테스트 모드 실행 → 실제 발송 없이 발송될 내용만 생성
6. 등록 완료 메시지와 "테스트 이메일 발송 내역"을 화면에 표시
7. 입력했던 값들을 모두 초기화하여 다음 방문객을 바로 입력할 수 있도록 함

`visit_id` 는 `등록시각(초 단위) + 임의문자 6자리` 조합으로 자동 생성되어 중복되지 않습니다.

## 5. 저장되는 방문 기록 항목 (`visitor_log.csv`)

`visit_id, registered_at, checkout_at, report_sent_at, visitor_name, visitor_company, visitor_phone, vehicle_number, visit_purpose, host_employee_id, host_name, host_department, host_email, visit_location, privacy_consent, signature_path`

- `checkout_at` : 방문객이 나간(퇴실) 일시. 방문객 등록 시점에는 알 수 없으므로 항상 빈 값으로
  시작하고, **관리자 페이지에서 나중에 입력/수정**합니다. 분 단위까지만 저장됩니다(초 단위 없음).
- `report_sent_at` : 이 방문 기록이 이메일 보고에 포함되어 **실제로 발송 완료된 시각**(KST).
  빈 값이면 아직 보고에 포함되지 않은 미발송 기록이라는 뜻입니다. 지금 단계(테스트 모드)에서는
  이메일 발송 테스트를 아무리 눌러도 이 값이 절대 바뀌지 않습니다.
- `signature_path` : 방문객이 화면에서 직접 그린 서명 이미지의 파일 경로 (`signatures/` 폴더 기준 상대경로)
- 이 열들이 추가되기 전에 저장된 예전 기록에도 해당 열이 없을 수 있는데, 이런 경우
  `utils.py` 가 자동으로 빈 값을 채워 넣으므로 관리자 페이지가 오류 없이 동작합니다.

## 6. 이메일 테스트 모드

`employees_dummy.csv` 의 이메일 주소가 모두 example.com 테스트 주소이기 때문에, 지금
단계에서는 실제 메일을 보내지 않습니다. 대신 등록 완료 후 화면의 "테스트 이메일 발송
내역" 영역과, 앱을 실행 중인 터미널(서버 로그)에서 다음 정보를 확인할 수 있습니다.

- 수신자 이름 / 수신자 이메일
- 메일 제목 (예: `[방문객 도착 안내] 홍길동 님이 방문하였습니다.`)
- 메일 본문 (방문자 성명, 소속, 연락처, 차량번호, 방문 목적, 방문 장소, 등록 시각 포함.
  차량번호를 입력하지 않으면 본문에 "미등록"으로 표시됩니다)
- 발송 예정 시각

### 향후 실제 이메일 발송으로 전환하려면

`app.py` 의 `send_test_email()` 함수를 실제 SMTP 발송 로직으로 교체하면 됩니다. 이때
아이디/비밀번호 등은 절대 코드에 직접 쓰지 말고, 아래 두 방법 중 하나로 분리해서 관리하세요.

- **환경변수 방식**: `.env.example` 을 복사해 `.env` 파일을 만들고 값을 채운 뒤,
  `python-dotenv` 등으로 불러오기 (`.env` 는 `.gitignore` 에 이미 포함되어 있어 커밋되지 않습니다)
- **Streamlit secrets 방식**: 로컬의 `.streamlit/secrets.toml` 에 값을 넣고 `st.secrets` 로 읽기

`app.py` 의 `get_setting()` 함수가 두 방식을 모두 지원하도록 이미 구조가 분리되어 있습니다.

## 7. 개인정보 및 보안 관련 처리

- 담당자 이메일 주소는 방문객 화면 어디에도 표시되지 않습니다. (내부 조회 전용)
- 비밀번호/API 키/메일 계정정보는 코드에 직접 작성하지 않으며, 환경변수/secrets 로만 다룹니다.
- 화면에는 개인정보 수집·이용 동의 문구와 보유기간 안내가 포함되어 있고, 동의하지 않으면
  등록이 진행되지 않습니다.
- 실제 방문 기록(`visitor_log.csv`)과 실제 직원 명단은 `.gitignore` 에 등록되어 있어
  GitHub 등 원격 저장소에 올라가지 않습니다. (지금 포함된 `employees_dummy.csv` 는
  테스트용 더미 데이터이므로 커밋해도 되지만, 실제 운영 데이터로 교체할 경우 파일명을
  `employees.csv` 등으로 바꾸어 `.gitignore` 규칙에 걸리도록 하세요)

## 8. 로컬 실행 방법

```powershell
# 1) (최초 1회) 가상환경 생성 및 활성화 - 선택 사항이지만 권장
python -m venv venv
venv\Scripts\Activate.ps1

# 2) 필요한 패키지 설치
pip install -r requirements.txt

# 3) 앱 실행
streamlit run app.py
```

실행 후 터미널에 표시되는 주소(기본값 `http://localhost:8501`)를 브라우저로 열면 됩니다.
휴대폰에서 테스트하려면 같은 Wi-Fi에 연결한 뒤 터미널에 표시되는 "Network URL" 주소로
접속하면 됩니다.

## 9. 관리자 페이지 (방문 기록 조회 · 엑셀 다운로드)

### 9-1. 접근 방법

`streamlit run app.py` 로 앱을 실행한 뒤, 화면 왼쪽 사이드바(모바일에서는 왼쪽 위 `>` 화살표)에서
**"관리자 페이지"** 를 선택하면 됩니다. 별도 명령어 없이 같은 서버에서 함께 열립니다.

### 9-2. 관리자 비밀번호 설정 방법

관리자 페이지는 비밀번호를 맞혀야만 방문 기록을 볼 수 있습니다. 비밀번호는 코드에 쓰여 있지
않고 환경변수 `ADMIN_PASSWORD` 값으로만 확인합니다.

1. `.env.example` 파일을 복사해 같은 폴더에 `.env` 파일을 만듭니다.
2. `.env` 파일의 `ADMIN_PASSWORD=change-me-before-use` 부분을 원하는 비밀번호로 바꿉니다.
   ```
   ADMIN_PASSWORD=여기에_실제_비밀번호
   ```
3. `.env` 파일은 `.gitignore` 에 포함되어 있어 GitHub에는 올라가지 않습니다.
4. 앱을 (다시) 실행하면 `utils.py` 가 `.env` 파일을 자동으로 읽어들입니다.
   (`.env` 대신 서버 환경변수나 `.streamlit/secrets.toml` 에 `ADMIN_PASSWORD` 를 넣어도 동일하게 동작합니다)
5. `ADMIN_PASSWORD` 를 설정하지 않으면, 관리자 페이지는 방문 기록을 보여주는 대신
   "비밀번호가 설정되어 있지 않다"는 안내 메시지만 표시합니다.

### 9-3. 방문 기록/서명 저장 위치

- 방문 기록: 프로젝트 폴더의 `visitor_log.csv`
- 서명 이미지: 프로젝트 폴더의 `signatures/` 폴더 안에 `{방문ID}_signature.png` 형식으로 저장
  (관리자 페이지에는 서명 이미지를 보여주는 화면이 없습니다. 서명은 등록 시 저장만 되고,
  필요하면 `signatures/` 폴더에서 파일로 직접 확인할 수 있습니다)

### 9-4. 관리자 페이지에서 할 수 있는 것

- 전체/오늘/이번 달 방문 건수, 차량번호 등록 건수 등 요약 지표 확인
- 방문일자 범위, 방문객 성명/회사명/차량번호/사내 담당자(부분 검색), 방문 목적/담당 부서/방문 장소
  (실제 기록에 있는 값 중 선택) 로 방문 기록 검색·필터링
- 최신 등록순으로 정렬된 방문 기록 표 확인. 표에서 **퇴실일시만 직접 입력/수정**할 수 있고,
  나머지 열(성명, 회사명, 방문 ID 등)은 실수로 바뀌지 않도록 편집이 잠겨 있습니다. 행을 새로
  추가하거나 삭제할 수는 없습니다.
- 현재 검색/필터 조건에 맞는 결과만 서식이 적용된 엑셀(.xlsx) 파일로 다운로드
  (첫 행 굵게, 자동 필터, 첫 행 고정, 열 너비 자동조정, 등록일시 날짜/시간 서식 통일)
- 아직 이메일 보고에 포함되지 않은(`report_sent_at` 이 빈) 방문 기록을 대상으로
  이메일 발송 테스트 실행

### 9-5. 퇴실일시 입력/저장 방식

- 방문 기록 표의 "퇴실일시" 칸을 원하는 값으로 바꾼 뒤(비우면 "아직 퇴실하지 않음"이 됩니다),
  **반드시 "퇴실일시 저장" 버튼을 눌러야** `visitor_log.csv` 에 실제로 반영됩니다. 칸만 바꾸고
  버튼을 누르지 않으면 파일은 그대로입니다.
- 저장 시에는 초 단위를 버리고 "년-월-일 시:분"까지만 저장합니다.
- 지금 화면에 검색/필터가 걸려 있어 일부 기록만 보이는 상태에서 수정하더라도, 항상 방문 ID를
  기준으로 `visitor_log.csv` 원본에서 정확히 그 줄만 찾아 수정하므로 다른 기록에는 영향이 없습니다.
- 실제로 값이 바뀐 기록만 저장되며, 아무것도 바꾸지 않고 저장 버튼을 누르면 "변경된 내용이
  없습니다" 라고만 표시되고 파일은 다시 쓰지 않습니다.

### 9-6. 이메일 발송 테스트 (미발송 방문 기록 전체 대상)

- 대상은 **현재 화면의 검색/필터와 무관하게, `report_sent_at` 이 비어 있는 방문 기록 전체**입니다.
  (예: 필터로 몇 건만 보고 있어도, 이메일 테스트는 필터와 상관없이 미발송 전체를 대상으로 합니다.
  이렇게 해야 늦게 등록된 방문 기록이 다음 보고에서 누락되지 않습니다)
- 수신자는 `report_recipients_dummy.csv` 에 있는 더미 명단(4명) 중에서 화면에서 직접 골라
  선택합니다. 한 명도 선택하지 않고 발송 버튼을 누르면 "수신자를 한 명 이상 선택해주세요"
  라고 안내하고 아무 일도 일어나지 않습니다.
- **지금은 테스트 모드만 구현되어 있어, 버튼을 눌러도 실제 이메일은 전혀 발송되지 않습니다.**
  대신 수신자별로 다음 정보를 화면과 서버 로그에서 확인할 수 있습니다: 수신자 이름/부서/이메일,
  메일 제목(`[테스트] 미발송 방문 차량 기록 N건`), 첨부파일명(`방문차량기록_YYYY-MM-DD.xlsx`),
  테스트 실행 시각, 첨부 대상 방문 기록 건수, 총 방문 차량 수.
- 테스트 버튼을 여러 번 눌러도 `report_sent_at` 값은 절대 바뀌지 않으므로, 실제 발송 기능을
  붙이기 전까지는 몇 번을 눌러도 "발송 완료 처리"가 되지 않습니다.
- 첨부되는 엑셀은 다운로드 버튼의 엑셀과 별개로 생성되며, 등록일시 오름차순으로 정렬되고
  맨 아래에 굵게/배경색으로 강조된 합계 행(`합계` / 차량번호 열에 `총 N대`)이 추가됩니다.
  `report_sent_at` 이나 서명 파일 경로 같은 내부 관리용 정보는 포함되지 않습니다.

### 9-7. 향후 실제 이메일 발송으로 연결하려면

`utils.py` 에 있는 아래 함수들은 실제 발송 기능을 붙일 때를 대비해 미리 역할이 나뉘어 있습니다.

- `get_unsent_records()` : 미발송 방문 기록 조회 (지금도 사용 중)
- `build_excel_bytes()` : 첨부용 엑셀 생성 (지금도 사용 중)
- `simulate_report_email()` : **테스트 모드 전용.** 실제 발송 없이 화면/로그에 내용만 표시
- `mark_reports_as_sent(visitor_ids, sent_at)` : **실제 발송에 성공한 뒤에만** 호출해서
  `report_sent_at` 을 갱신하는 함수. 이미 만들어져 있지만, 지금은 어디에서도 호출하지 않습니다.

실제 SMTP 발송 기능을 추가할 때는, `simulate_report_email()` 을 호출하는 자리에 진짜 이메일을
보내는 함수를 새로 만들어 연결하고, **그 발송이 선택한 수신자 전원에게 성공적으로 끝난 경우에만**
`mark_reports_as_sent()` 를 호출하도록 구현하세요. 테스트용 시뮬레이션 함수와 실제 발송
함수가 서로 섞이지 않도록 분리해 둔 것이 핵심입니다. SMTP 계정 정보는 `send_test_email()` 과
마찬가지로 `.env`/`st.secrets` 로만 관리하고 코드에 직접 쓰지 마세요.

### 9-8. Streamlit Cloud 배포 시 주의사항

Streamlit Community Cloud 등 컨테이너 기반 호스팅에 배포하는 경우, 컨테이너가 재시작되거나
앱이 새로 배포되면 로컬 파일 시스템의 내용(= `visitor_log.csv`, `signatures/` 폴더)이
**영구적으로 보존되지 않을 수 있습니다.** 즉, 재배포/재시작 시 그동안 쌓인 방문 기록과 서명
이미지가 사라질 수 있습니다. 실제 운영 환경에서는 데이터베이스나 Google Sheets, 외부 스토리지
등 영구 저장소로 옮기는 것을 권장합니다.
